# Spec: SynthGuard `evaluation-core`

## Status

Approved for implementation. This specification defines the second module in `CAPABILITY_MAP.md` and depends on the implemented `data-core` contract.

## Assumptions

1. The MVP evaluates one real CSV against one synthetic CSV generated by `data-core`.
2. Statistical fidelity and privacy-risk evidence are mandatory; ML utility is optional and runs when the user selects a classification target.
3. The module measures evidence but never decides whether a dataset passes; deterministic decisions belong to `quality-gate`.
4. Evaluation remains local, CPU-compatible, offline, and free.
5. Exact and near-copy metrics are risk indicators, not proof of anonymity or regulatory compliance.
6. SDMetrics provides statistical quality and DCR baseline protection; transparent project-owned checks calculate exact and near duplicates.
7. Classification utility uses a fixed, documented scikit-learn baseline rather than optimizing a model for each dataset.

## Objective

Build a framework-independent Python module that compares a source dataset with one synthetic candidate and returns JSON-serializable evidence across three dimensions:

- **Statistical fidelity:** whether individual distributions and column relationships remain similar.
- **Privacy risk:** whether rows are copied or unusually close to real records.
- **ML utility:** whether a model trained on synthetic rows performs similarly on held-out real rows.

The intended consumer is `quality-gate`; future Streamlit and MCP modules display the same typed result without reimplementing metrics.

### User stories

- As a data scientist, I can see an overall statistical score and the weakest columns or relationships.
- As a privacy-conscious developer, I can detect exact copies and suspiciously close synthetic records.
- As an ML engineer, I can compare a fixed classifier trained on real versus synthetic data using the same held-out real test set.
- As an interface developer, I receive typed evidence, warnings, and stable machine-readable failures.

## In Scope

- Input and metadata validation for one real/synthetic pair.
- Exact schema and column-order comparison.
- SDMetrics quality report: overall score, column shapes, and column-pair trends.
- Per-column quality details and a bounded list of weakest results.
- Exact row-match count and rate after deterministic null normalization.
- Mixed-type nearest-neighbor distance evidence with bounded row sampling.
- SDMetrics DCR baseline protection score.
- Optional binary or multiclass classification utility using weighted F1.
- Real-data train/test split with synthetic and real models evaluated on the same held-out real test set.
- Typed contracts, stable errors, offline tests, and non-sensitive fixtures.

## Out of Scope

- Pass/fail thresholds, candidate ranking, or winner selection.
- Formal differential privacy, k-anonymity, regulatory certification, or anonymity claims.
- Membership-inference attacks requiring an external model or service.
- Regression, forecasting, text, image, audio, and relational evaluation.
- Hyperparameter tuning or claiming that one baseline represents every downstream workload.
- Streamlit pages, MCP tools, databases, hosted storage, and background workers.

## Tech Stack

- Existing Python 3.12 and `uv` project
- Existing pandas, Pydantic, SDV, and SDMetrics dependencies
- scikit-learn for preprocessing, nearest-neighbor evidence, and fixed classifiers
- pytest, pytest-cov, Ruff, and mypy for quality gates

No dependency may make a network call during import, evaluation, or tests.

## Public Interface

Only names exported from `synthguard.evaluation_core` are public.

```python
from pathlib import Path

from pydantic import BaseModel, Field


class EvaluationRequest(BaseModel):
    real_csv: Path
    synthetic_csv: Path
    metadata_json: Path
    classification_target: str | None = None
    random_seed: int = 42
    max_privacy_rows: int = Field(default=5_000, ge=100, le=50_000)


def evaluate_candidate(request: EvaluationRequest) -> "EvaluationResult": ...
```

`EvaluationResult` contains:

- Source and synthetic SHA-256 fingerprints.
- Row and column counts.
- `StatisticalQualityResult`.
- `PrivacyEvidenceResult`.
- Optional `ClassificationUtilityResult`.
- Structured warnings and elapsed evaluation time.

### Statistical result

- `overall_score`, `column_shapes_score`, and `column_pair_trends_score`, each bounded to `[0, 1]`.
- Per-column shape scores with column names only, never source values.
- Up to ten weakest column or pair results, sorted deterministically.

### Privacy evidence

- `exact_match_count` and `exact_match_rate`.
- `near_duplicate_count` under a documented normalized-distance threshold.
- Minimum, fifth-percentile, and median synthetic-to-real nearest-neighbor distances.
- `dcr_baseline_protection_score` from SDMetrics, bounded to `[0, 1]`.
- Sampling metadata so large-dataset results remain reproducible and interpretable.

### Classification utility

- Target name, detected class count, train/test sizes, and weighted-F1 metric name.
- `real_train_score`: classifier trained on real training rows, evaluated on held-out real rows.
- `synthetic_train_score`: classifier trained on synthetic rows, evaluated on the same held-out real rows.
- `utility_retention`: synthetic score divided by real score, with an explicit warning when the baseline score is zero.
- The fixed baseline uses median imputation and scaling for numeric features, most-frequent imputation and one-hot encoding for categorical features, and logistic regression with documented parameters.

### Error contract

Pydantic rejects malformed request objects with `ValidationError`. Valid requests may raise `EvaluationCoreError` with `code`, safe `message`, and structured `details`.

Stable operational codes include:

- `FILE_NOT_FOUND`
- `FILE_TOO_LARGE`
- `INVALID_CSV`
- `INVALID_METADATA`
- `SCHEMA_MISMATCH`
- `EMPTY_DATASET`
- `TARGET_NOT_FOUND`
- `UNSUPPORTED_TARGET`
- `INSUFFICIENT_CLASSES`
- `STATISTICAL_EVALUATION_FAILED`
- `PRIVACY_EVALUATION_FAILED`
- `UTILITY_EVALUATION_FAILED`

Public failures never include raw rows, complete cell values, estimator internals, stack traces, or unrestricted filesystem paths.

## Behavioral Requirements

### Validation

- Real and synthetic datasets must be non-empty and contain exactly the metadata columns in the same order.
- The evaluator must not modify either dataset or metadata artifact.
- Fingerprints are calculated before evaluation.
- Metadata is loaded through the locked current SDV `Metadata` API and validated.
- Classification targets must exist in both datasets and contain at least two real training classes.

### Statistical fidelity

- Use the current `sdmetrics.reports.QualityReport`, not deprecated single-table imports.
- Disable verbose output and convert report frames into typed, deterministic records.
- Bound and validate all scores before returning them.
- Report metric failures explicitly rather than silently substituting a perfect or zero score.

### Privacy risk

- Normalize nulls deterministically for exact-row comparison.
- Exclude direct identifier columns from distance calculations because IDs distort proximity.
- Fit numeric scaling and categorical encoding on the combined bounded sample solely for distance comparability.
- Record the distance threshold and sampled row counts in the result.
- Seed every sampling operation from the request.
- Describe exact copies and DCR as risk evidence, never as a privacy guarantee.

### ML utility

- Split real data before fitting preprocessing or classifiers to prevent test leakage.
- Evaluate both classifiers against the same untouched real test set.
- Use stratification when class counts permit it; otherwise fail clearly rather than silently changing methodology.
- Do not tune models against the held-out test set.
- Record all fixed model and split parameters in the result.

## Code Style

- Follow root `AGENTS.md` and existing `data-core` patterns.
- Keep SDMetrics and scikit-learn behind small adapters.
- Type every public function and use immutable Pydantic results.
- Sort derived detail records deterministically.
- Keep metric calculation pure after validated frames enter the module.

```python
def evaluate_candidate(request: EvaluationRequest) -> EvaluationResult:
    pair = load_evaluation_pair(request)
    statistical = evaluate_statistical_quality(pair)
    privacy = evaluate_privacy_evidence(pair, request)
    utility = evaluate_classification_utility(pair, request) if request.classification_target else None
    return assemble_result(pair, statistical, privacy, utility)
```

## Testing Strategy

### Unit tests

- Contract bounds and JSON serialization.
- Schema, metadata, target, and class validation.
- Exact-copy counting including null values.
- Distance normalization and deterministic sampling.
- Utility preprocessing fitted without access to held-out labels.
- Stable error codes and value-safe messages.

### Integration tests

- Compare controlled real, high-quality synthetic, and deliberately poor synthetic fixtures.
- Verify good synthetic data scores better than shuffled or collapsed data.
- Verify copied rows raise exact and near-duplicate evidence.
- Train real and synthetic classifiers and evaluate both on the same real holdout.
- Evaluate an actual `data-core` generated artifact end to end.

### Test quality bar

- At least 90% statement coverage for `src/synthguard/evaluation_core`.
- All tests run locally without network access or GPU.
- Metric expectations use ranges or ordering where exact floating-point values would be brittle.
- Fixed seeds make sampling and ML tests repeatable.

## Boundaries

### Always

- Preserve source artifacts unchanged.
- Return metric provenance, sampling details, and limitations.
- Keep training and preprocessing free from held-out test leakage.
- Use bounded samples for potentially quadratic distance work.
- Run focused tests and all static quality gates before committing.

### Ask first

- Add a new metric, model family, problem type, dependency, or external service.
- Change the fixed distance threshold or ML baseline methodology.
- Persist evaluation results outside the caller's future report workflow.
- Add threshold decisions that belong to `quality-gate`.

### Never

- Claim that a candidate is anonymous, compliant, or safe.
- Log raw rows, target values, identifiers, or complete nearest-neighbor examples.
- Tune against the held-out real test set.
- Hide failed metrics, replace missing results with perfect scores, or collapse evidence into an unexplained grade.
- Send any dataset, metadata, or metric input over the network.

## Success Criteria

- A valid real/synthetic pair produces a deterministic, JSON-serializable evaluation result.
- Statistical results expose overall, column-shape, and relationship scores plus deterministic weak areas.
- Privacy evidence detects deliberately copied rows and reports bounded, reproducible distance evidence.
- An optional classification experiment compares real-trained and synthetic-trained models on the same held-out real rows.
- Invalid schema, metadata, targets, classes, and metric failures produce stable structured errors without source-value leakage.
- End-to-end evaluation accepts artifacts produced by both `data-core` generation methods.
- Focused tests pass offline with at least 90% statement coverage and all project quality gates green.

## Open Questions

No blocking questions. Regression utility, formal privacy mechanisms, and pass/fail thresholds remain explicitly deferred.
